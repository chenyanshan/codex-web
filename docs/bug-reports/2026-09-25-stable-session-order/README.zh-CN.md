# 会话列表稳定排序、归档与缓存打开体验

日期：2026-09-25。

## 用户确认的行为

| 操作或事件 | 列表表现 |
| --- | --- |
| 新建会话、发送新指令、追加指令 | 会话前移 |
| 助手输出、工具执行、完成、失败、等待审批 | 在原位置更新内容和提示 |
| 打开后返回、后台恢复、重连 | 保持顺序和列表阅读位置 |
| 收藏列表 | 使用相同的稳定排序规则 |

运行、审批、失败、未读结果提示继续保留。管理控制台的审计列表继续使用原来的审计更新时间顺序。

## 实现

- 新增持久化的 `listOrderAt`，仅由新建或明确接受的新指令推进。保留 `updatedAt`、`lastInputAt` 原有缓存新鲜度及送达判断用途。自动目标续跑和状态通知不推进排序。
- 旧会话首次从已有摘要更新时间初始化一次，随后持久保存；这不是从完整历史回溯的精确最后输入时间。初始化不读取完整历史。缺失时间用稳定的零值，同时间按 ID 排序。
- 前后端都按相同字段排序。游标升级到第 2 版，继续绑定身份及筛选条件；旧游标明确拒绝，前端自动重新获取一次。
- 待发送消息立即前移，但使用固定的临时排序时间；重试不反复刷新时间，确认送达后回归服务端值，避免客户端时钟偏差污染持久顺序。
- 列表刷新重新校验已经加载的范围，保留分页懒加载；不直接保留未经重新授权校验的旧尾页。身份、请求代次、筛选条件变化时丢弃迟到结果。
- 设置写入通过实例内队列进入原有文件锁，避免旧会话并发初始化时争锁超时。跨进程锁、原子分区存储和缓存边界保持。
- 归档保护改为检查目标会话，解决“当前会话运行时不能归档另一个空闲会话”的静默返回。确认框从已知摘要或当前会话取数据，解决当前会话不在可见列表页时无法打开的问题。运行中的目标仍受保护。
- 有缓存或已有可见消息时，不再插入随后消失的“正在加载历史／刷新执行状态”横幅。空内容初次加载、主动翻历史页、失败及重试反馈仍保留；实际请求、校准和阅读锚点逻辑不变。

清理了没有生产调用的旧辅助函数以保持首屏资源预算，没有提高预算阈值。现有 session 视觉回退补丁仍可独立反向检查。

模拟摘要目录与临时磁盘存储的测量：100 个旧会话首次首屏约 118 ms，1,000 个目录首屏约 100 ms，剩余初始化约 3.1 s；1,000 条均持久化，无锁超时、无历史读取。重新创建运行时后的首屏约 65 ms。这是同机 fixture 测量，不代表真实网络或用户设备端到端耗时。

存储不可写时，列表仍可读，排序在当前进程内保持；已被 Codex 接受的指令不会因为排序写入失败变成可重试的提交失败。磁盘失败期间的排序无法承诺跨重启保持。

浏览器验证使用 Chromium 的桌面、手机竖屏和窄屏视口；不等同于真实手机设备测试。测试期间未归档真实用户会话。旧审计截图被测试覆盖的部分已从本轮开始前的检查点恢复。
