# 管理控制台只读会话按需加载

2026-09-25。用户要求：进入时先看最早的内容，向下滑动再继续加载，避免长会话一次下载完整历史。

## 原因与改动

原界面虽然最多挂载 80 条消息，但打开和刷新都请求完整会话详情；网络传输、解析、附件修复和历史整理仍处理整份历史。

现在使用 `/api/admin/sessions/:id/timeline`，复用正常会话的分页器、缓存历史投影、请求取消、超时、重复请求合并和阅读锚点。

- 首次只取最早 50 条，从顶部开始。
- 接近底部时由向下阅读的手势触发后续 50 条，保留“显示更新消息”按钮；最多挂载 80 条消息。
- 失败保留已有内容，显式重试同一页，不自动连续拉取全部历史。
- 跳到最新只取末尾一页；回前台刷新按当前阅读锚点取一页，用户在慢请求期间继续阅读时，以用户位置为准。
- 每页重新检查管理员权限与会话映射。只读模式、附件访问、正常会话草稿和返回位置保持。
- 旧详情接口保留兼容，但管理会话的打开、翻页和刷新不再调用它。服务端页大小上限为 100，当前前端每页请求 50。

前端沿用项目 `frontend-design` 与既有会话样式；本次没有更换主题、字体或会话布局。管理专属分页辅助逻辑放在原有按需加载的 `admin-ui.js` 中。

- `public_ui.test.ts`：已有及本轮用例 463 项通过，随后新增的刷新竞态用例单独通过，共 464 项。

## 优化能力与限制

受影响编号：OPT-01、08、09、10、11、13、15、17、18、19、20、21。分页复用正常会话的恢复与缓存机制；新增用例验证分页边界、请求归属、阅读位置和权限。OPT-06 通过原会话草稿返回测试回归；其余能力未修改相应执行或存储路径。

底层 provider 目前不提供历史分页。服务端缓存未命中时，仍需读取完整历史并建立受容量限制的投影；本次减少的是发给浏览器的数据和页面处理量，并复用该投影缓存，不能据此承诺任意长会话首次读取都无等待。没有测量真实生产长会话的打开耗时。

实施前快照位于主机外部状态目录的 `source-checkpoints/admin-history-20260925T005805Z`。既有 session 样式回退补丁仍可独立应用；不得用仓库 HEAD 覆盖本轮之前尚未提交的改造。

部署状态记录在本目录 `verification.json`；完成测试不代表服务已重启。
