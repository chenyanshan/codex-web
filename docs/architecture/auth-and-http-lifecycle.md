# Authentication and HTTP lifecycle

Authentication state mutations use the shared asynchronous cross-process file lock. Password replacement and old-session removal commit together through an atomic rename. Token checks inspect the current file inode/version before reusing a token-hash index; cached validity is never accepted solely because a time interval has not elapsed. Display-only `lastSeenAt` is persisted at most once per device every 30 seconds, with a fresh transaction read before writing.

Device sessions expire 90 days after creation. Existing sessions without `expiresAt` use the same creation-time deadline. The authenticated device controls are `GET /api/auth/sessions`, `DELETE /api/auth/sessions/:id`, and `POST /api/auth/sessions/revoke-others`. Returned objects contain no token hashes. Trusted-team password replacement also invalidates that user's sessions, and login insertion checks that the verified credential has not changed.

Each committed single-user auth state has a private `.backup` mirror. Corrupt primary state fails closed; it is never automatically replaced by an older backup, which could restore a revoked password or session. Run the existing local `codex-web auth set-password` command to recover: it preserves malformed primary JSON as `.corrupt-<timestamp>`, sets the supplied new password, and revokes all sessions. Backups and quarantine files contain password hashes and must retain private permissions; they are not portable login tokens. Identity-store corruption also fails closed and requires explicit operator recovery; do not restore older user sessions from backups.

Private SSE delivery revalidates the token and the target session/project permissions before each frame. Idle connections recheck within one second. Logout and device revocation recheck active streams before responding, closing only streams whose credentials no longer authorize access. Unrelated devices and users remain connected. Share streams additionally have an expiry timer and check the deadline after asynchronous authorization, before every replay/live/control frame. Shares remain opt-in.

Static bodies, ETags, gzip and Brotli representations are prepared once per loaded build/content version, with bounded retention for dynamic app-shell titles. `/api/metrics` is authenticated and administrator-only; it returns aggregate request/setup latency, event-loop delay, replay/reset counts, storage scans, and cache statistics, without URLs, prompts, tokens, or file contents. SSE request timing ends when headers are ready, not when a long-lived stream closes.

Session-file `?preview=1` limits text/Markdown/HTML previews to 256 KiB and returns `X-Content-Truncated`, `X-Content-Total-Bytes`, and `X-Content-Preview-Bytes`. The download URL supplies the complete file. Binary/full downloads support one byte range, retain the existing 64 MiB file gate, and stream through 64 KiB buffers with four concurrent handles. The same path, opened-descriptor, symlink, ownership, MIME, and HTML sandbox checks apply.

Scheduled terminal waits default to a six-hour deadline and support caller cancellation. Runtime shutdown/restart cancels the wait. Failure attempts a bounded turn interrupt, never archives the incomplete session, unsubscribes, and releases the task lock. The created session remains available for inspection. HTTP shutdown closes SSE, allows ordinary requests up to one second to drain, then destroys remaining sockets and drains scheduled storage maintenance before stopping the runtime.
