# 随身 Codex：活动面板视觉与交互改造计划

日期：2026-09-29。更新：2026-09-30，工作区实现完成，截图与检查见[面板验收](../../audits/2026-09-30-activity-panel.md)及[集成记录](../../audits/2026-09-30-portable-codex-integration.zh-CN.md)，未部署生产 UI。属于[官方能力复用计划](2026-09-29-portable-codex-official-parity.md)的第一批工作，不能等新功能全部堆进旧面板后再美化。

## 1. 代码证据和问题

本次检查 `public/work-details-view.js`、`public/app.js` 和 `public/styles.css`；实际查看已有 `docs/audits/2026-09-19-connection-work-evidence/work-live-mobile-portrait.png`。旧截图只说明当时的渲染，不冒充当前工作区/部署版截图。新方案尚未进行真实浏览器渲染验收。

| 现状证据 | 对手机使用的影响 | 改造方向 |
| --- | --- | --- |
| renderWorkItem/renderProgress 同时显示当前活动、原始标题、完成数、分类数、运行状态、新活动按钮 | 顶部多行信息竞争；用户仍需读命令才能知道发生什么 | 当前状态为主，次级信息最多一行；计数从主视觉退到活动列表标题 |
| summary 使用 `10px 52px minmax(0,1fr) auto` 四列 | 类型、状态挤占标题，长中文/命令阅读破碎 | 改为小图标、主文案区域、展开符号；次要状态放文案第二行 |
| 工作标题直接截取原始 command/title 第一行 | 技术细节先于操作含义，长路径在窄屏失去辨识度 | 确定性展示“运行命令/读取文件/修改文件”及目标；原始命令在详情完整保留 |
| 顶部和行内 running 都使用 success 色，状态点带光晕 | 正在执行、成功和异常的语义区分不足 | 运行用中性/信息色，错误/重试按语义色；完成不铺满绿色 |
| 顶部工作摘要 sticky，面板标题也独立占高度 | 小屏/横屏可读活动面积被压缩 | 仅面板标题和最短状态固定，详细摘要随列表滚走 |
| 输出/文件/diff/原始数据连续嵌套 | 展开后像调试对象浏览器；滚动目标难辨认 | 普通活动展开一级；长输出或 diff 在同一面板切换详情视图 |
| CSS 同一组件有基础规则、dialog 覆盖和多处媒体覆盖 | 改动容易相互抵消，难维持所有主题 | 收敛组件规则，保留全局 token；不再末尾追加补丁覆盖 |

已有正确实现必须保留：44px 触摸区、详情模块懒加载、分页、暂停跟随/新活动提示、事件 ID、captureReadingState/restoreReadingState、captureDialog/restoreDialog、横向阅读位置及焦点恢复。不能因换皮删除这些逻辑。

## 2. 设计方向

主体仍是对话；活动面板是查看过程的辅助层。延续现有字体、主题和图标系统，通过层级、对齐、间距改变观感，不另起一套配色，不增加装饰性渐变、阴影卡片或进度仪表。

主工作对象：当前任务活动。主动作：展开查看、返回聊天；停止和追加指令仍在原输入区，避免到处重复按钮。面板内只在确有阻塞时提供明确的“查看待回答问题/审批”入口。

比较后的布局选择：保留当前手机底部面板、桌面居中浮层，不引入常驻右侧栏。理由是可以复用焦点/关闭/背景滚动锁，避免重新设计桌面分栏及手机路由。面板高度先维持现有合理范围，再用真机截图校准；不添加拖拽高度和复杂手势。

## 3. 信息结构与线框

聊天页平时只显示一条可点的短摘要，使用现有状态入口，不另加常驻大卡片。最终回复保持视觉主角。具体工具名只有可信数据存在时显示，默认“运行命令”，不额外调用模型生成漂亮摘要。

```text
聊天页，输入区上方：
  正在运行命令                                  ›

异常时：
  模型连接重试中                                ›
  最近未收到新进展 8 分钟

展开活动：
┌─────────────────────────────────────────┐
│ 本轮活动                            关闭 │
│ 正在运行命令                            │
│ npm run typecheck                       │
├─────────────────────────────────────────┤
│ 活动记录                      查看更早  │
│ [图标] 修改文件                      › │
│        app.js · 已完成                  │
│ [图标] 运行命令                      › │
│        npm run typecheck · 进行中       │
│ [图标] 检查代码                      › │
│        子代理名称 · 等待结果            │
│                                         │
│                     [查看 3 条新活动]   │
└─────────────────────────────────────────┘
```

这是信息层级草图，文案来自 fixture 示例，不代表当前任务状态。实施时标题/状态避免复述；例如“运行命令”行已表达类型，就不再放“执行”徽章。

层级规则：

1. 当前状态一句话，必要时一行补充。计划只在确实收到计划时出现折叠入口，不占一张常驻卡。
2. 活动列表默认以现有时间顺序与窗口展示，更新原条目，不为 started/updated/completed 各插一行。
3. 不因状态变化把条目自动搬到顶部；失败在顶部摘要提示并提供定位，保留用户正在读的顺序。
4. 收到真实 question/approval 时，聊天区也必须可发现，不能藏在面板深处。
5. 官方计划的“完成 2/4 步”与“已收到 12 条活动”区别展示；活动数不是任务完成比例。

## 4. 展开和长内容

- 默认活动行折叠，首次展开只显示有意义的命令、结果或文件摘要；无详情不显示无意义展开按钮。
- 允许保持多个条目展开，沿用现有 ID 记忆；不强制手风琴自动收起正在看的另一条。
- 普通输出显示有界预览。长输出/diff 用“查看完整可用内容”进入同一面板的详情视图，返回恢复原条目的位置。服务端只保留片段时明确写“查看已保留输出”，不能声称完整。
- 不出现“弹窗上再盖弹窗”。原始字段只在详情的低频诊断区显示，不加入新的全局开发者模式。
- 文件行保留可辨识文件名与末级目录；展开后可看完整路径。摘要可以截断，但完整信息不能只能靠 hover title。
- 日志默认折行；diff 保留代码缩进、局部横向滚动。整个页面不横向溢出；避免每个输出块都出现独立纵向滚动条。
- 复制完整可用内容仅在数据确实存在时提供；局域网 HTTP 下处理剪贴板不可用，显示可选中文本，不静默失败。

## 5. 视觉规格

复用现有语义变量 `--panel`、`--panel-2`、`--text`、`--muted`、`--border`、`--info`、`--warn`、`--danger`、`--focus`；不修改全局主题配色。面板表面一层，详情用一个次级表面，行间细分隔，不给每条活动加卡片和阴影。

字体使用现有系统字体；命令/path/输出才使用已有等宽字体。面板标题 16px/600，活动主文案 14px，次级文字 12–13px，行高约 1.5；跟随用户字体偏好，不用缩字塞四列。手机主行 48–56px 起，长文案可增高；触摸目标至少 44px。

内边距以 12/16px 为主，组内 4/8px，详情块间 12px；图标视觉尺寸约 16px，来自现有 UI.icon，禁止新增图标包。状态数字使用等宽数字。色彩只强调重试/错误/待处理和键盘焦点。

运行中不使用成功绿及外发光；完成保持低干扰中性色，失败配文字与语义色，离线明确标最后同步时间。动画只用于用户展开/关闭的轻反馈，尊重 reduced-motion；不对每条新日志做入场动画。

## 6. 弱网与状态契约

| 状态 | 呈现与行为 |
| --- | --- |
| 尚无工具活动 | 简短显示“暂未收到工具活动”，不放假列表或完成百分比 |
| 首次加载详情 | 面板结构立即出现，局部提示；可以关闭，不挡住整个应用 |
| 懒加载模块失败 | 显示内置的最小摘要和重试入口；不能因 renderer 未到达使已知异常也不可见 |
| 有缓存、正在校准 | 保留原列表，细提示“正在同步”；不换成整屏骨架 |
| 离线 | 保留已加载内容并标“离线，显示上次记录”；未缓存详情有明确不可用状态 |
| 上游重试 | 顶部可见重试，不自动展开日志、不抢滚动 |
| 新活动到达、用户在看旧记录 | 不自动滚动，保持展开/焦点/选中文本，合并新活动计数 |
| 详情请求失败 | 保留已有预览，就地重试该条；不能重发任务 |
| 终态到达 | 状态就地更新，不自动关面板、收起全部条目或跳到最新 |
| 权限撤销或换会话 | 关闭敏感详情、取消失效请求，迟到响应不能串会话 |

主状态和问题入口不得依赖大型详情模块下载。继续懒加载详细 renderer；关闭面板不新建后台请求，展开不读取全量历史。沿用现有 SSE 和分页，不增加轮询器、数据库或持久化所有日志。

## 7. 实施顺序及文件

**V0：现状和原型。** 用当前代码 fixture 生成真实手机/桌面基线，制作同一组件的紧凑列表原型，覆盖正常、重试、失败、长输出。先看渲染效果，再接更多官方能力；旧截图仅供问题定位。

**V1：先修现有面板。** 在 `work-details-view.js` 改摘要/活动行/详情结构；在 styles.css 收敛该组件规则；app.js 只调整容器和最少事件接线。保留 capture/restore 和分页机制，并让按需渲染的大输出不在折叠时就构建全部 DOM。加入实际有用的状态和长内容回归。

**V2：接 S1/S3 新数据。** 新的重试/压缩/计划/子代理/工具信息进入同一布局。避免为每种能力单独增加一张面板或 Tab。数据不存在时不展示空占位组。

**V3：压力及弱网验收。** 依照下方浏览器矩阵修正。任何小屏溢出、层级不清、丢阅读位置都必须修复；通过类型检查不能替代视觉验收。

## 8. 浏览器验收

实施必须执行 render → 手机/桌面截图 → 实际查看 → 操作 → 查控制台/资源失败 → 修复 → 重拍。目标尺寸 320、390×844、768、当前 900px 面板断点两侧、1440×900，并补手机横屏和虚拟键盘。

所有现有主题先自动检查基本尺寸/对比度，人工查看默认浅色、深色及至少一个高对比差异主题。测试 200% 缩放、中文/英文长文案、长路径、超长代码行、100+ 活动分页及多项展开。

行为回归包括：离线打开缓存面板、模块加载失败后重试、用户向上读时流式更新、展开长输出后返回、切会话迟到请求、SSE reset、状态从 running 到 retrying 到 completed、失败后继续阅读、Esc/触摸关闭及焦点返回。

验收标准：第一眼能找到当前状态；无重复的大块摘要和伪进度；正常活动视觉克制、异常容易发现；手机正文宽度不被固定类型列吞掉；无第三层浮窗、无全页横向滚动；列表更新不收起已展开内容；关闭后草稿和聊天阅读位置不变。记录实际截图与未验证项，不宣称本规划已完成视觉验收。
