# Codex Web 零基础使用与原理说明

> 适用对象：已经拿到 Codex Web 网址、账号和密码，但此前几乎没有使用过 AI
> 的受邀用户。
>
> 文档版本：2026-07-31。本文描述的是当前这个 Codex Web 项目，不代表所有 AI
> 产品都具有相同能力。

## 你的使用信息

由管理员在交付前填写：

```text
正式 HTTPS 地址：
你的登录账号：
允许使用的项目：
问题联系人：
```

密码请通过单独的安全渠道提供，不要写进本文档，也不要和网址、账号一起发到群聊。

## 先记住这三句话

1. Codex Web 不是一个新的 AI 模型，而是一个让你通过浏览器远程操作 Codex 的网页控制台。
2. 页面看起来像聊天软件，但它背后的 AI 可以读取文件、修改文件和执行电脑命令，所以不能把它当成普通聊天机器人。
3. 你拿到的网页账号和密码只用于登录这个网站，不能拿它登录 Codex App、Claude Code、OpenClaw 或 ChatGPT。

如果你只想问常识、写一段文案或随便聊聊，普通 Chat 类产品通常更合适。如果任务需要查看项目、处理一批文件、运行程序或真正交付文件，再使用 Codex Web。

## 1. 这个项目是什么

Codex Web 是一套自托管的 Codex 网页控制台。“自托管”是指：网站和 AI 的实际执行环境都运行在提供者自己的 Mac 上，而不是运行在你的手机里。

可以把它理解成：

- 你的手机或电脑浏览器是“遥控器”；
- Codex Web 后端是“接线员和安全门”；
- 宿主 Mac 是“真正干活的工作台”；
- Codex 是会理解任务、使用工具并完成工作的“智能执行者”；
- Skills 是交给 Codex 的“专项工作手册”。

它适合完成这类任务：

- 阅读和整理项目资料；
- 修改代码、文档或配置；
- 分析报错并运行检查；
- 根据要求生成 Markdown、HTML、PDF、图片或其他项目文件；
- 上传文件或图片，让 Codex 在当前项目中处理；
- 在同一个会话里持续跟进一项工作；
- 查看执行过程、文件改动和最终结果。

它不是：

- 一个完全运行在手机上的 AI；
- 一个普通聊天网站的换皮版本；
- 一个让陌生人彼此隔离使用的云端 SaaS；
- 一个永久在线、完全离线也能工作的手机 App；
- Dify 或 Coze 那样用来搭建和发布各种 AI 应用的低代码平台。

## 2. 它是如何工作的

整体链路如下：

```text
你的手机或电脑浏览器
        |
        | HTTPS + 登录凭证 + 你的任务
        v
Codex Web 后端（运行在宿主 Mac）
        |
        | 校验账号、项目权限和会话
        v
本机 Codex runtime / app-server
        |
        | 读取项目、调用 Skills、执行命令、修改文件
        v
宿主 Mac 上的真实项目目录
        |
        | 实时返回文字、状态、命令和文件改动
        v
你的浏览器页面
```

一次任务通常会经历以下过程：

1. 你在浏览器登录，服务端验证账号和密码。
2. 浏览器保存一个不透明的设备登录令牌，之后通常不必每次重新输入密码。
3. 你选择项目，打开或新建会话，输入任务并发送。
4. 后端检查你是否有权访问该项目，然后把任务交给宿主 Mac 上已经登录的 Codex。
5. Codex 阅读当前项目、项目规则和可用 Skills，按需要读取文件、修改文件或执行命令。
6. Codex Web 把“正在思考、正在执行命令、修改了哪些文件、是否失败、最终回答”等事件实时传回页面。
7. 对话、应用状态、上传文件和生成结果主要保存在宿主 Mac，而不是保存在你的手机中。

### 四种身份不要混淆

| 身份 | 用途 | 谁持有 |
| --- | --- | --- |
| Codex Web 账号 | 登录这个网页、决定能看哪些项目 | 每位网页用户 |
| 浏览器设备令牌 | 让这个浏览器保持登录 | 当前浏览器 |
| 宿主机 Codex 登录 | 调用 Codex 模型和能力 | 服务提供者的 Mac |
| 宿主 Mac 系统用户 | 决定进程实际能读写哪些文件、能运行什么命令 | 服务提供者 |

你使用的是宿主机已有的 Codex 能力和项目环境。网页不会把宿主机的 Codex 密码或凭据发给你。模型用量、可选模型和服务可用性也主要取决于宿主机的 Codex 配置。

### 使用成立的必要条件

以下条件缺一不可：

- 宿主 Mac 已开机并联网；
- Codex Web 服务正在运行；
- 你的设备能通过有效网址访问该服务；
- 应使用 HTTPS 登录，不能在不可信的明文 HTTP 网络中输入密码；
- 宿主机的 Codex 登录仍然有效；
- 你的网页账号仍有效，并且拥有目标项目权限。

所以，网页打不开不一定是你的账号错误，也可能是宿主 Mac 关机、服务停止、网络入口失效或宿主 Codex 登录过期。

## 3. 第一次使用

### 登录

1. 使用提供者发给你的正式 HTTPS 地址。
2. 输入分配给你的账号和密码。
3. 不要在群聊、公开文档或截图中展示密码。
4. 只在自己的设备或可信浏览器中选择保持登录。
5. 在公共设备上使用后要退出登录，并清除该网站的数据。

网页账号最好一人一个，不要多人共用同一账号。这样才能正确区分会话归属和操作记录。

### 开始一个任务

1. 先确认当前项目是否正确。项目选错，AI 看到和修改的文件也会错。
2. 不确定时新建一个会话；同一件事的后续要求继续在原会话中发送。
3. 第一次使用先选择 `Read only（只读）` 或 `Ask before changes（修改前询问）`。
4. 模型和推理强度不懂就保持默认。
5. 清楚写出目标、材料、限制和完成标准，然后发送。
6. 观察页面中的运行状态、命令、文件改动和错误提示。
7. 打开生成文件或检查结果，不要只看 AI 最后一段“已经完成”的文字。

### 三种权限模式

| 页面选项 | 实际含义 | 适合场景 |
| --- | --- | --- |
| `Read only` | 只查看和分析，不修改项目 | 初次了解项目、审阅、总结 |
| `Ask before changes` | 在项目范围内工作，部分敏感动作会请求确认 | 大多数普通任务，推荐初学者使用 |
| `Full access` | 可以用宿主用户的较大权限直接执行，通常不会逐步询问 | 仅限明确、可信、可恢复的任务 |

当前项目的新会话默认值可能是 `Full access`。初学者不要把“AI 会先问我”当成安全保证，应主动改成更保守的权限。即使点击“停止”，已经执行的命令和已经写入的文件也不会自动回滚。

### `Default` 和 `Plan` 模式

- `Default`：让 Codex直接着手完成任务。
- `Plan`：先调查和规划，适合范围不清楚、风险较高或你想先看方案的任务。

对于删除、批量改名、大范围重构、部署、发外部消息等任务，建议先用 `Plan`，确认方案后再执行。

### 模型和推理强度

- 模型决定使用哪一种 Codex 模型；可选项由宿主机当前 Codex CLI 提供。
- 推理强度越高，通常越适合复杂分析，但可能等待更久、消耗更多用量。
- 初学者不需要追求“最高”，先保持默认；结果不够好时再提高推理强度或拆小任务。

## 4. 怎样给 AI 下任务

AI 不要求你会写“提示词咒语”。最有用的是把事情说完整。

一个稳妥的任务包含五项：

```text
目标：最终要得到什么
材料：应该查看哪些文件、附件或背景
范围：允许处理什么，不允许处理什么
过程：是否先分析、是否可以修改、是否需要运行检查
完成标准：怎样算做完，结果放在哪里
```

### 只分析、不修改

```text
请先只读分析这个项目，不要修改文件，也不要执行有副作用的命令。
用不懂技术的人也能理解的语言说明：项目用途、主要模块、当前风险和建议的下一步。
不确定的地方请明确标注，不要猜测。
```

### 修改文档

```text
请把当前项目的使用说明改成面向第一次使用 AI 的人。
保留原有技术说明，不修改代码。
完成后告诉我修改了哪个文件，并检查目录和链接是否有效。
```

### 处理附件

```text
请阅读我上传的文件，提取关键结论并生成一份 Markdown 报告。
不要改变原文件。报告写入当前项目的 docs 目录，并在回答中给出可打开的文件链接。
```

### 高风险任务先规划

```text
先检查现状并给出执行计划，暂时不要修改、删除或发布任何内容。
计划里列出会影响的文件、风险、备份方式和验证方法，等我确认后再执行。
```

### 使用中的几个习惯

- 一次只给一个清晰目标；大任务让 AI 先拆分。
- 同一件事继续使用原会话，完全不同的事情新建会话。
- 明确写“不要删除”“不要联网发送”“不要修改某个目录”等边界。
- 对重要修改要求 AI 运行检查，并说明检查结果。
- 对数据、合同、财务、医疗或生产环境结果进行人工复核。
- AI 说“完成”不等于一定正确，应查看文件、差异和测试结果。

## 5. 页面里还能做什么

当前项目除了发送文字，还支持：

- 项目和会话管理；
- 收藏、归档和恢复会话；
- 实时查看运行状态和工作过程；
- 停止正在运行的 turn；
- 上传文件和图片；
- 在桌面浏览器中直接粘贴剪贴板里的文件或图片；
- 打开会话中生成或链接的 Markdown、HTML、PDF 和常见图片；
- 弱网下恢复最近的会话和排队中的纯文本消息；
- 在管理员开启后生成有时限、可撤销的只读分享链接；
- 通过管理员或高级用户配置的 Webhook 接收外部任务。

这些能力有几个限制：

- 弱网恢复不是离线运行；真正开始任务仍需连接宿主 Mac。
- 附件不是永久网盘，可能因保存期限或空间策略被清理。
- 任务停止或服务重启时，正在执行的 turn 可能中断。
- 只读分享链接虽然不能发任务，但链接本身相当于查看密码，不能公开传播。
- Webhook 能在宿主 Mac 上触发真实工作，应由管理员或懂安全的高级用户配置。

## 6. 如果没有这个网页，应该用什么

先明确一个关键事实：如果你只有 Codex Web 的网址、账号和密码，却没有宿主电脑的使用权，那么 Codex App、Claude Code 和 OpenClaw 都不是可以直接登录的替代入口。你需要各产品自己的安装、账号、权限和项目环境。

| 选择 | 更适合谁 | 特点 | 对零基础用户的建议 |
| --- | --- | --- | --- |
| Codex App | 想在自己的电脑上用图形界面处理本地项目的人 | 桌面端规划、审阅和交互式工作，与 Codex 生态最接近 | 有自己的电脑和 Codex 权限时优先考虑 |
| Claude Code | 熟悉终端、代码仓库和命令行的人 | 在本地终端中工作的编码智能体，使用 Anthropic 的账号和生态 | 功能强，但不建议完全零基础者独立配置 |
| OpenClaw | 愿意自托管并配置通用智能体、渠道和扩展的人 | 更偏开放的智能体框架，具体能力和安装方式随所用版本或项目而异 | 先确认准确项目来源，再由技术人员部署和加固 |
| 普通 Chat 产品 | 只想问答、写作、总结和头脑风暴的人 | 上手最简单，通常不直接操作宿主机真实项目 | 简单问题优先使用 |

选择建议：

- 想要最接近当前 Codex 本地工作体验的桌面替代：选择 Codex App。
- 已经熟悉终端，并明确想使用 Claude 生态：选择 Claude Code。
- 想自己搭建跨渠道、可扩展的通用智能体系统：评估准确版本的 OpenClaw。
- 只需要问问题或写内容：直接使用普通 Chat 产品。
- 只拿到本项目网页账号、希望在手机远程完成宿主项目工作：继续使用 Codex Web，这是它解决的核心问题。

不同工具的会话、账号、订阅、Skills 和配置通常不会自动互通。即使它们打开同一个本地目录，能看到同一批文件，也不代表会同步对话记录或权限设置。

## 7. Skills 是什么，如何安装

### Skills 是“工作手册”，不是新的 AI

Skill 通常是一个包含 `SKILL.md` 的目录，也可以附带参考资料、模板、脚本和资源文件。它告诉 Codex：什么情况下使用这套方法、按什么步骤做、需要读取哪些材料、如何检查结果。

例如：

- 做公司研究时使用固定调查框架；
- 写某类文档时套用团队模板；
- 发布前运行一组检查脚本；
- 在 Codex Web 中需要时读取当前网页用户和项目信息。

Skill 不能保证结果绝对正确，也不会自动给模型增加原本没有的系统权限。它只是让可重复任务更规范。

### 谁负责安装

在这个项目里，Skills 安装在运行 Codex Web 的宿主 Mac 上，不是安装在你的手机浏览器里。普通网页用户应把 Skill 名称和可信来源发给管理员，由管理员安装和审核。

不要把网页账号密码发给所谓的 Skill 安装者。安装 Skill 也不需要网页用户的密码。

### 当前项目使用的安装位置

本项目约定的本机目录是：

```text
~/.codex/skills/<skill-name>/SKILL.md
```

一个最小 Skill 的结构类似：

```text
~/.codex/skills/example-skill/
  SKILL.md
  scripts/       # 可选
  references/    # 可选
  assets/        # 可选
```

### 安装当前仓库自带的 Skill

仓库自带 `codex-web-user-context`，作用是在确有需要时，让 Codex 读取当前网页用户和项目的有限上下文。它不包含密码或登录令牌，也不能用来代替后端权限检查。

管理员在仓库根目录执行：

```bash
mkdir -p ~/.codex/skills/codex-web-user-context
cp -R skills/codex-web-user-context/. ~/.codex/skills/codex-web-user-context/
```

本项目的 macOS 自动安装脚本通常已经完成这一步，不需要网页用户重复安装。

### 安装其他 Skill 的标准流程

1. 确认 Skill 的准确名称、来源仓库和版本。
2. 管理员先阅读 `SKILL.md`，并检查其中引用的脚本、命令、网络地址和外部工具。
3. 把整个 Skill 目录放到宿主 Mac 的 `~/.codex/skills/<skill-name>/`，确保 `SKILL.md` 位于目录根部。
4. 如果当前 Codex 界面提供启用/停用选项，确认该 Skill 已启用。
5. 新建一个会话测试；若目录仍未出现在 Codex 的 Skill catalog 中，再重启 Codex Web 服务。
6. 用一个低风险、可验证的小任务确认 Skill 是否按预期触发。

也可以在宿主 Mac 的 Codex App 或 Codex CLI 中，把可信 Skill 的仓库地址交给具备 Skill 安装能力的 Codex，让它完成复制和检查；最终仍应由管理员确认安装目录和内容。

### 如何使用 Skill

大多数情况下，Codex 会根据 Skill 的描述自动判断是否需要使用。你也可以明确说：

```text
请使用 <skill-name> 完成这项任务，并在结果中说明做了哪些检查。
```

如果没有触发，常见原因包括：

- Skill 没有安装在运行服务的那个 Mac 用户下；
- 目录层级错误，找不到 `SKILL.md`；
- Skill 被禁用；
- 旧会话没有刷新到新的 Skill catalog；
- 任务与 Skill 的适用描述不匹配；
- 这是其他产品的扩展格式，并不兼容 Codex Skill。

### 安全规则

- 只安装可信来源的 Skill，最好固定到已审查的版本。
- Skill 里的文字也可能诱导 AI 执行危险命令，不能因为它是 Markdown 就认为没有风险。
- 特别检查删除文件、上传数据、安装软件、访问密钥、修改系统配置和发外部消息的步骤。
- 多人共用同一宿主 Mac 时，全局安装的 Skill 可能影响其他用户的 Codex turn。
- Claude Code、OpenClaw 或其他平台的扩展不能默认视为与 Codex Skills 兼容。

## 8. 这种形式和普通 Chat 有什么区别

Codex Web 的输入框也是对话形式，但核心是“通过对话驱动智能体执行工作”，不只是“通过对话得到一个回答”。

| 对比项 | 普通 Chat | Codex Web 这种 Agent 方式 |
| --- | --- | --- |
| 主要产物 | 一段回答、建议或生成内容 | 回答，以及项目中的真实文件和执行结果 |
| 可见上下文 | 当前对话、上传内容、已授权连接器 | 当前项目文件、项目规则、会话、Skills 和工具结果 |
| 行动能力 | 通常以回答为主 | 可读取、修改文件并执行 shell 命令 |
| 工作过程 | 多为一次问答 | 会调查、计划、调用工具、检查、失败后重试 |
| 持续性 | 以聊天上下文为主 | 同一项目和会话可持续推进一项工作 |
| 风险 | 主要是回答错误或隐私泄露 | 还包括真实文件改动、命令副作用和外部操作风险 |
| 适合任务 | 问答、写作、翻译、灵感 | 编码、文件处理、项目分析、可验证的交付工作 |

两者不一定使用不同的“智力”。真正的差别主要来自：Agent 是否拥有工具、文件环境、长期项目上下文和执行权限。

一个简单判断方法：

- 只需要“告诉我答案”时，用 Chat。
- 需要“到项目里把事情做完并留下结果”时，用 Codex Web 或其他 Agent。

## 9. 和 Dify、Coze 有什么区别

Dify 和 Coze 的重点通常是“搭建一个 AI 应用或自动化流程，再提供给其他人使用”；Codex Web 的重点是“把一台 Mac 上已经可用的 Codex，通过安全网页远程操作”。

| 对比项 | Codex Web | Dify / Coze |
| --- | --- | --- |
| 产品定位 | 本地 Codex 的远程工作控制台 | AI 应用、Bot 和工作流搭建平台 |
| 主要用户 | 需要直接完成项目工作的操作者 | 应用搭建者、运营团队和应用终端用户 |
| 核心对象 | 项目、会话、文件、命令、Codex turn | 工作流节点、知识库、模型、插件、渠道和发布应用 |
| 执行位置 | 提供者的同一台宿主 Mac | 平台云端或自行部署的服务端环境，取决于产品和部署方式 |
| 本地文件能力 | 能直接使用宿主机授权范围内的真实项目 | 通常通过知识库、API、插件或工作流连接数据 |
| 搭建方式 | 安装后直接作为 Codex 工作台使用 | 需要设计提示词、流程、知识库、变量和发布渠道 |
| 标准化程度 | 适合开放式、探索式项目任务 | 更适合重复、结构化、面向许多用户的固定流程 |
| 隔离边界 | 多人模式只适合完全互信的人 | 取决于平台部署、租户和权限体系，不能一概而论 |

选择建议：

- 想让 AI 直接进入本地项目，读文件、改文件、运行命令：Codex Web。
- 想做客服机器人、内部知识问答、表单流程或面向许多人的固定 AI 应用：Dify 或 Coze。
- 想把一次探索性任务逐渐变成稳定业务流程：可以先用 Codex Web 验证，再考虑用 Dify、Coze 或代码固化流程。
- 两者可以集成，但不应让未经审核的外部流程直接获得宿主 Mac 的高权限 Webhook。

## 10. 安全、隐私和责任边界

### 这是“互信成员共用一台工作电脑”，不是彼此隔离的云空间

多人模式中的项目权限、角色和审计主要约束网页界面和 HTTP API。所有 Codex turn 最终仍可能以同一个宿主 Mac 系统用户执行，共享同一套 Codex 登录和文件环境。

因此：

- 只应向完全互信的人开放账号；
- 不应把它当成陌生客户之间的安全租户隔离；
- 不可信用户必须使用不同的系统用户、容器或独立主机；
- 网页显示“你不能看某项目”不等于底层操作系统已经建立了强隔离。

### 普通用户必须遵守

- 不上传无权处理的个人信息、商业秘密、密钥或客户数据。
- 不要求 AI 搜索宿主机上与当前项目无关的目录。
- 不让 AI 在未经授权的情况下发邮件、发布内容、调用生产系统或购买服务。
- 不随意使用 `Full access`。
- 不把密码、设备令牌、Webhook key 或只读分享链接发到公开渠道。
- 发现项目选错、命令异常或范围失控时立即停止，并联系管理员。

### 管理员必须负责

- 宿主 Mac、Codex 登录、HTTPS 网络入口和服务生命周期；
- 创建独立用户、分配最小项目权限、停用离开的用户；
- Skills 和外部工具的审核、安装、升级与撤销；
- 项目备份、日志和存储空间；
- 模型用量、订阅和成本；
- 重要项目的操作系统级隔离；
- Webhook、公开分享和远程入口的安全配置。

## 11. 常见故障

| 现象 | 可能原因 | 先怎么做 |
| --- | --- | --- |
| 网页完全打不开 | 宿主机关机、服务停止、网址或网络入口失效 | 检查网址和网络，联系管理员确认宿主服务 |
| 能打开但不能登录 | 密码错误、账号停用、HTTPS/浏览器问题 | 不要反复猜密码，确认账号并联系管理员重置 |
| 登录后看不到项目 | 尚未分配项目权限或项目被停用 | 联系管理员分配正确项目 |
| 一直显示连接中或重连 | 手机网络不稳、HTTPS 入口中断、服务重启 | 刷新一次；仍失败就记录时间并联系管理员 |
| 显示 `Failed`、401 或 403 | 宿主 Codex 登录失效、账号权限不足或服务配置异常 | 保留错误文字，交给管理员处理 |
| 显示 `Stopped` | 你主动停止、服务重启或 turn 被中断 | 先检查是否已有部分改动，再决定是否继续 |
| AI 没有使用某个 Skill | 未安装、未启用、目录错误或任务不匹配 | 把 Skill 名称和来源发给管理员检查 |
| 生成的文件打不开 | 文件被移动、清理、超出预览范围或格式不支持 | 让 AI确认实际路径；必要时让管理员检查宿主文件 |
| AI 结果不符合要求 | 目标、材料或完成标准不清楚，也可能是模型判断错误 | 指出具体差异，让它检查现状后修正，不要只说“重做” |
| 点击停止后文件仍变了 | 停止不会撤销已经完成的操作 | 检查改动，使用版本控制或备份恢复 |

向管理员报告问题时，提供：发生时间、项目名、会话标题、页面错误文字和必要截图。不要在截图中包含密码、令牌或敏感文件内容。

## 12. 常见问题

### 我关掉网页，任务还会继续吗？

只要宿主 Mac、服务和 Codex runtime 正常，已经提交的任务通常仍在宿主机运行。重新打开页面后会尝试恢复状态，但服务重启等情况仍可能中断任务。

### 手机需要安装 Codex 吗？

不需要。手机只是浏览器或 PWA 遥控界面，实际 Codex 安装在宿主 Mac。

### 能安装到手机桌面吗？

可以。iPhone/iPad 用 Safari 打开后选择“分享 -> 添加到主屏幕”；Android 用 Chrome 选择“Install app”或“Add to Home screen”。正式使用应通过 HTTPS。

### 我能看到宿主机的 Codex 密码吗？

不能，也不需要。网页只使用分配给你的 Codex Web 账号，Codex 凭据保留在宿主机。

### 我能让它处理任何电脑文件吗？

不应该。你只能处理获得授权的项目和数据。技术上能否访问更多位置取决于会话权限和宿主机配置，但“能访问”不等于“被授权访问”。

### AI 修改错了怎么办？

立即停止后续操作，说明哪里不对，先要求它只读检查改动。重要项目应使用 Git 或其他备份机制恢复。不要依赖 AI 自己记住原内容。

### 删除会话会删除项目文件吗？

会话记录和项目文件是不同对象。不要假设归档或清理会话会撤销文件改动，也不要假设删除项目文件会自动删除会话记录。

### Skills 会自动对所有用户生效吗？

安装在宿主用户全局 Skills 目录中的 Skill 可能出现在多个项目和用户的 Codex catalog 中；是否实际触发还取决于启用状态、项目上下文和任务内容。因此全局 Skill 应由管理员统一审核。

### Codex Web、Codex App 和 ChatGPT 是同一个东西吗？

不是。它们可能都使用 OpenAI 的 Codex 或相关模型能力，但产品入口、运行位置、工具权限、会话存储和账号体系不同。这个项目是第三方自托管网页控制台，不是 OpenAI 官方 Codex App 本身。

## 13. 术语表

| 术语 | 小白解释 |
| --- | --- |
| AI 模型 | 负责理解和生成内容的核心能力 |
| Agent / 智能体 | 不只回答，还会规划、调用工具并执行任务的 AI |
| Codex | OpenAI 面向软件和项目工作的编码智能体 |
| Codex Web | 本项目提供的自托管远程网页控制台 |
| 宿主机 | 真正运行服务、Codex、命令和项目文件的 Mac |
| Project / 项目 | 一组允许 Codex 工作的文件和目录 |
| Session / 会话 | 围绕一项持续工作的对话记录 |
| Turn | 你发送一次任务后，Codex 从开始到完成的一轮执行 |
| Runtime | 实际启动和运行 Codex 的本机执行环境 |
| Skill | 可复用的专项工作说明、参考资料或脚本包 |
| Prompt | 你发送给 AI 的任务说明 |
| Token | 可能指模型计量单位，也可能指登录令牌；两者不是一回事 |
| PWA | 可以从浏览器添加到手机桌面的网页应用 |
| Webhook | 让其他系统通过受保护的网络请求向 Codex Web 发送任务的入口 |
| HTTPS | 加密的网页连接；远程登录必须使用它保护密码和令牌 |
| RBAC | 在网页层按用户和角色分配功能及项目权限 |

## 14. 给受邀用户的一页式操作清单

每次开始前：

- 确认网址是正式 HTTPS 地址。
- 确认当前项目正确。
- 不确定时使用只读或修改前询问。
- 不上传无权处理的敏感资料。

发送任务时：

- 写清目标、材料、范围、限制和完成标准。
- 大任务先让 AI 规划。
- 明确哪些文件不能修改，哪些外部动作不能执行。

任务完成后：

- 查看真实文件和改动，不只看最终回答。
- 检查 AI 是否运行了必要的验证。
- 重要结果由人复核。
- 不再使用公共设备时退出并清除网站数据。

## 15. 给管理员的交付清单

在把账号交给 AI 新手前，管理员至少应确认：

- 给每个人创建独立账号，使用临时密码并要求安全保存；
- 只分配必要项目和角色；
- 提供正式 HTTPS 地址，不让用户通过明文 LAN HTTP 输入密码；
- 将新用户的默认权限调整为保守模式，或明确教她每次检查权限；
- 说明哪些目录、数据和外部操作被授权；
- 确认项目有 Git 或其他备份；
- 验证宿主机 Codex 登录和服务自启动；
- 审核已安装 Skills 和 Webhook；
- 说明故障联系人、响应时间和紧急停止方式；
- 用户离开时撤销账号、设备 session、分享链接和相关 Webhook key。
