# 工作详情、连接状态与 Markdown 优化

本轮处理三个明确反馈：工作内容难读、无法判断当前进展；服务重启时 502 消失且各设备状态不同；Markdown 预览过窄、希望接近 GitHub 风格。

## 工作详情

顶部显示当前活动的类型和实际命令或文件；没有活动正在执行时显示最近一项活动。本轮仍在运行时，即使已有命令全部结束，也不会把整轮工作标成完成。

- 显示已完成活动数、目前已收到的活动总数和失败数。总数随新活动增长，是工具活动统计，不是任务完成百分比或预计剩余时间。
- 命令、目录、耗时、输出、错误分别展示。JSON 包装中的文本会解开，终端 ANSI 颜色控制字符不再混进正文；低频元数据收进“原始数据”。
- 文件差异按增加、删除、上下文区分，保留正负号和统一差异中的行号；窄屏仅在差异区域横向滚动。
- 展开旧活动后暂停追随列表，新活动仍更新顶部信息，并提供查看新活动的入口。
- 实时更新和窗口缩放保留展开状态、原始数据折叠状态、焦点和横向阅读位置。对话框只有一个纵向滚动容器。
- 工作详情按需加载，加载中、失败重试、关闭期间完成加载及跨会话切换都有处理。

沿用输出预览上限，超限明确提示“预览已截断”。没有收到的差异和工作步骤不会推测生成。

## 服务重启与 502

连接状态独立于任务状态和缓存的“就绪”。可恢复的 HTTP 错误会显示“连接中断 · HTTP 502 · 正在重连”，页面重绘和无关请求成功不会把它盖掉。

返回前台、网络恢复及定期检查会验证服务和当前会话状态。活动流仍未恢复时继续提示；确认服务、会话及所需的活动流恢复后才清除。验证期间保留已有消息和草稿。迟到响应和旧账户请求不能覆盖新账户或已确认恢复后的状态。

这里修复的是 502 的显示和恢复逻辑。单实例 Web 服务重启期间，外部反向代理仍可能短暂返回 502；没有通过隐藏报错声称实现零停机。

## Markdown

桌面文档占用预览区可用宽度，采用 GitHub 风格的标题分隔线、列表间距、简洁引用、浅底代码及边框表格。保留手机局部横向滚动、下载、草稿恢复、连续缩放和文件权限约束。详见 [Markdown 预览记录](2026-09-19-markdown-preview.md)。
