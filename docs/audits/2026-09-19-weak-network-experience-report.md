# Codex Web 弱网体验专项检查

日期：2026-09-19。审计基线为重命名功能上线后的工作区，页面版本 `36e07a0a6454d38f1f38`。检查覆盖源码、Chromium 手机与桌面页面，以及延迟、网关错误、断网和恢复实验。第 1–4 节保留当时的发现和建议，原始数据与源码 SHA-256 见[测量记录](2026-09-19-weak-network-evidence/measurements.json)。四项 P1 问题现已修复并重启服务，实施与最终验收见第 5 节。

## 结论

优先处理四处请求协调与恢复问题：流式连接的临时错误被当成任务结束、初始认证失败后不自动恢复、模型请求阻塞列表展示、状态请求阻塞历史展示。这些问题直接决定用户看到的是“还能用、正在恢复”，还是“卡住、失败、只能刷新”。其中两处等待已经取得的数据，应先消除这类额外延迟。

现有本地草稿、持久发送箱、服务端提交去重、事件游标续传、历史缓存和静态资源缓存可以继续复用。普通 JSON 和静态文件已支持 gzip/Brotli；SSE 已有心跳、背压和重放控制。

## 2. 后续体验优化

| 顺序 | 建议 | 用户能感知的变化 | 实施边界 |
| --- | --- | --- | --- |
| 第一批 | 修复上述四项，提取统一请求与连接恢复模块 | 内容到了就能看；暂时掉线能自动恢复；不会把网络错误显示成任务结束 | 使用现有布局与紧凑提示；保留已移除的搜索和状态筛选的当前状态 |
| 第二批 | 完善发送的确认状态：已在设备保存、等待连接、等待服务器确认、已确认；复用现有 submissionId | 用户知道消息是否安全保存、是否已被服务器接受 | 只对有幂等保障的操作自动重试；响应丢失时继续使用原提交 ID，不能创建第二个任务 |
| 第二批 | 为读请求建立统一的截止时间、合并与有限重试规则 | 避免一直转圈、恢复时重复加载；失败有就地重试入口 | 建议普通读取初始截止时间 10–15 秒，需结合实际链路调参；不要把这个值套用到长连接和文件上传 |
| 第二批 | 连接与缓存提示统一：显示缓存内容、最近同步时间、正在恢复；前台与 online 触发一次合并恢复 | 不用依靠刷新猜测状态；已读消息和未发草稿保持稳定 | `navigator.onLine` 只是信号，还要看实际请求是否成功；只读本地缓存不能授予新的服务端操作权限 |
| 第三批 | 附件单独展示进度、支持取消和失败重试；按需要提供图片缩小选项 | 弱网上传有进展反馈，失败不用重选所有文件 | 当前 `uploadAttachments()` 是一次性 FormData fetch，未接入取消、超时或上传进度；分片续传需要新增服务端协议，后置实施；代码截图与精细图片应允许保留原图 |
| 第三批 | 若真实手机数据表明缓存容量不足，再将最近会话缓存逐步迁至 IndexedDB，并设置容量/过期上限 | 增加可离线查看的最近会话，减少重复下载 | 当前历史缓存限制为 5 个会话、每个最多 80 条；保留账户与权限边界，不缓存全部私有接口响应 |

当前心跳间隔 15 秒，客户端以 30 秒无事件判断陈旧，每 10 秒检查一次；按代码推算，静默断流可能需要约 30–40 秒才触发检查。应先修复错误分类，再用真实手机和代理链路测量后决定是否缩短，避免弱网中增加无效重连。无需为了该问题迁移到 WebSocket。

## 3. 已有能力的实际验证

在已完成 Service Worker 缓存的 localhost 环境断网并刷新，页面和草稿约 **44ms** 恢复，最近用户消息和最终回复保留。见[离线截图](2026-09-19-weak-network-evidence/phone-offline-cached-session.png)。测试时间线补齐了真实 runtime 的 `final` / `final_answer` 标记；通用浏览器 fixture 原本缺少这些字段，不能把由此触发的权限过滤误判成生产数据丢失。

项目已有“新会话响应丢失后，刷新继续使用同一 submissionId”的浏览器回归；刚完成的 80 项浏览器验收覆盖了该用例。发送箱将消息先持久化，服务端按提交 ID 去重，这应作为后续发送状态和恢复逻辑的基础。

PWA 缓存需要浏览器安全上下文。手机若直接访问局域网 `http://IP:端口`，通常不能注册 Service Worker；通过 HTTPS 入口访问才能获得完整的页面离线启动能力。本项目仍保持隧道/反向代理配置在项目外的边界。这次 localhost 的离线结果不能直接代表手机 LAN HTTP 入口。

## 4. 建议的验收标准

| 测试条件 | 应达到的行为 |
| --- | --- |
| 模型请求挂起 30 秒，认证与列表正常 | 会话列表及时出现，可打开已有会话；模型选项有独立的加载/失败反馈 |
| 状态延迟 5 秒，历史立即返回；反过来再测一次 | 已到达的部分在下一次正常渲染更新中显示；另一部分独立等待与重试 |
| 流式重连返回一次 502/503，随后正常 | 显示正在重连，恢复原任务，答案不重复，不能自行显示任务结束 |
| 初始化中断网，随后联网；Wi-Fi 与蜂窝切换；锁屏后返回 | 自动恢复身份确认和必要数据；合并重复恢复信号，保持草稿与滚动位置 |
| 服务端已收消息但确认响应丢失 | 重试使用同一提交 ID，服务端只执行一次，消息状态最终与服务器一致 |
| 已缓存页面离线刷新 | 最近允许展示的对话与草稿可恢复；缓存内容和实时执行状态可分辨 |
| 400–800ms RTT、256–512kbps 带宽、间歇中断 | 核心文本操作可用；重试有上限/退避，不用不断刷新，不在弱网时批量重复拉取数据 |

最后一行是下一轮压力与真机验收条件，尚未把它作为本次实测结果。当前证据来自故障注入和 Chromium；真实 iOS Safari/PWA、物理蜂窝切换及外部代理的缓冲行为仍待验证。

复现方式：先启动 `node packages/codex-web/test/browser/fixture-server.mjs --port=41743`，再运行 `node docs/audits/2026-09-19-weak-network-evidence/measure.mjs`。实验只使用合成会话与 fixture token，不调用真实 Codex 模型或修改真实会话。

## 5. 已完成的修复与部署

四项 P1 已完成。认证与列表展示不再等待模型、设置、项目等可独立加载的数据；普通 GET 设为 12 秒截止时间，模型加载提供独立反馈与重试。状态与历史分别到达、分别渲染，等待不再被误报为失败。网络恢复、窗口重新进入前台与定时检查会合并恢复认证；短暂冷却期间的恢复信号会延后执行。SSE 的 408/425/429/500/502/503/504 按临时连接错误恢复，保留运行中的任务状态与已有退避计时；401/403 继续按认证失败处理。

实现中同时补齐三个边界：身份尚未重新确认时，持久发送箱不能提交；模型迟到时不能覆盖用户已经修改的草稿参数；会话状态与时间线按可比较的时间信息判断新旧，缺乏可靠版本时保留活动任务证据，避免固定相信某一个接口而误清除跨设备正在运行的任务。原有导航归属、重命名响应隔离、草稿和滚动位置保护继续保留。
