# 随身 Codex Web 集成验收

日期：2026-09-30。工作区实现与验证记录；尚未部署，也没有升级宿主机 CLI 或重启当前服务。

## 实现范围

- 官方 app-server 继续负责执行和模型重试。新增有界活动投影，把重试、压缩、计划、工具、子代理最近观测、token 用量与 diff 摘要接入现有 SSE；不写入聊天时间线，不改变消息排序。
- 活动面板保留手机底部面板和桌面浮层，用图标、主文案、展开按钮替换四列摘要。输出和 diff 按需展开，保留阅读锚点、焦点、暂停跟随和有界分页。
- 结构化问答沿用官方请求身份与 schema；答案提交先保存回执，再尝试交付。断线只查回执，不自动重答；敏感答案不写入浏览器草稿或服务端回执文件。
- 设置区区分 Web build、磁盘 CLI、运行中 app-server、协议基线。维护预约持久化、只保留一个任务，并与执行入口共享闸门；活动或全局状态未知时等待。支持已识别的 npm 官方安装来源，固定稳定版本，校验后应用。
- 运行时切换清理易失缓存并旋转 SSE epoch，关闭旧事件流以触发现有快照恢复。已确认聊天记录保留。

## 集成中发现并处理的问题

1. 问题卡模块状态在 bootstrap 后初始化，首次 render 会触发 TDZ；初始化已移到 bootstrap 前。
2. 新增界面让首屏压缩预算超标；保持原有 140 KiB 阈值，通过按需资源拆分收敛，不提高阈值。
3. 维护原先只拦 start/steer；补上 createSession，并核对 loaded threads 的持久化目标，避免仅看本地目标缓存漏判。等待阶段允许暂停/清除目标，应用阶段仍禁止新执行。
4. 过大的问题事件不可截断成“可回答的半个问题”；改为快照校准标记，保持事件字节上限。
5. 运行时重启不能只换进程而保留旧 SSE；新增 epoch 通知关闭订阅，恢复时走原有 reset 流程。
6. 原缓存缩放测试 fixture 没有会话排序初始化字段，首次读取会合法写入新 manifest。fixture 预置排序字段后继续断言每个 revision 只加载一次，外部更新仍要求重新读取；未放宽计数断言。
7. 问答和更新模块最初手动编码 body，既有 apiFetch 会再次编码。改为传结构化对象，并用真实 API 客户端到 HTTP 路由验证 payload 和单次交付，避免模拟函数掩盖协议错误。
