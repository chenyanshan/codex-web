# Codex Web 前端设计复审与改造建议

日期：2026-09-25。依据项目 [frontend-design](../../.agents/skills/frontend-design/SKILL.md)、当前工作区源码、用户提供的审批截图，以及隔离浏览器 fixture 的实际页面检查。

**审批请求、全局设置窗口、管理控制台是三个优先整体重做的区域。主聊天界面继续沿用用户认可的风格。** 本文记录扫描结果与后续实施要求；本轮新增审查文档、浏览器检查脚本和截图，没有修改产品源码、切换运行底座或重启线上服务。

## 用户要求与设计边界

- 用户明确：“样式丑爆了说的是那个审批请求。”审批需要重新设计卡片、字号、间距、边框、按钮与状态反馈，不能仅整理展示字段或改文案。
- 用户提出管理控制台可以整体重构。评估范围包含导航、页面结构、列表、编辑表单、会话审计、系统状态和确认操作。
- 用户随后补充：“还有全局设置窗口，也有点奇怪。”因此全局设置提升为 P1，包含窗口位置、宽高、模态层级和控件样式的整体调整，不能仅增加内容分组。
- 保留现有五种主题、两种会话布局及项目整体风格。当前聊天壳、消息气泡、输入框和文件阅读页作为延续的视觉基础。
- [21 项优化保留基线](../architecture/2026-09-25-existing-optimizations-baseline.zh-CN.md)继续有效。美化不能丢失弱网恢复、草稿、阅读位置、增量更新、请求归属或授权检查。
- 此前的 [app-server 前端验收](2026-09-25-app-server-frontend-design.md)主要验证审批发送状态及功能边界，不构成此次样式复审的通过结论。页面没有横向溢出，也不能证明按钮内部文字完整或设计协调。

## 扫描结论

P1 表示优先实施的产品问题或明确缺陷；P2 表示随后处理的局部问题。视觉评价、功能缺陷和体验建议分别说明。

| 编号 | 优先级 | 结论 | 建议 |
| --- | --- | --- | --- |
| FD-01 | P1 | 审批请求的视觉结构与聊天界面不协调；授权标签有语义问题，窄屏按钮还会截字 | 重做审批组件，并同时整理可用动作与授权范围 |
| FD-02 | P1 | 管理台沿用多套列表、表单和确认样式，信息层级与空间分配需要统一 | 整体重构管理台页面体系 |
| FD-03 | P1 | 首次访问关键脚本下载失败，或启动时读取存储抛错，页面停在加载画面 | 补启动错误与恢复界面，统一安全存储读取 |
| FD-04 | P1 | 工作详情的键盘 Tab 导航在关闭按钮与第一项之间循环 | 修复可聚焦元素收集与焦点循环规则 |
| FD-05 | P2 | 上传失败时附件卡片的重试按钮被挤成两行，并超出预留列宽 | 重新组织附件的名称、状态、重试与移除区域 |
| FD-06 | P1 | 全局设置窗口的位置与模态表现不一致，控件规格和内容分组也不统一 | 重做设置窗口外壳、控件与分组导航 |
| FD-07 | P2 | 中英文切换不完整，部分标题与字段仍混用语言 | 补齐文案与日期格式的一致性 |
| FD-08 | P2 | 分享失效等空白/错误页只有一行原始错误，缺少下一步提示 | 按错误类型提供简短说明和适当恢复入口 |

### FD-01：审批请求需要整体重新设计

证据：[桌面审批](2026-09-25-frontend-design-review-evidence/desktop-approval.png)、[手机审批](2026-09-25-frontend-design-review-evidence/mobile-approval.png)、[320px 英文审批](2026-09-25-frontend-design-review-evidence/compact-approval-retro-current.png)、[五主题对照](2026-09-25-frontend-design-review-evidence/themes-approval.jpg)。长命令和规则内容为根据用户截图构造的 fixture，未运行所展示的审批命令。

视觉问题已经体现在组件结构中：标题 13px、正文与字段名 12px、右上角类型 11px 且强制大写；底部三个等宽按钮则是 16px。大量细小字段被压在一起，动作区占据过高视觉权重。审批使用通用 `.card` 和 `renderSummary()`，缺少与对话一致的留白、阅读节奏及审批专属层级。仅更换背景色不能解决。

还有两项需要同时修复的实际问题：

- 三个按钮固定输出。“本会话允许”对应的选项在存在执行规则建议时优先发送 `acceptWithExecpolicyAmendment`，没有发送 `acceptForSession`。它们是不同协议决定，不能使用同一授权范围文案。对于不支持该选项的请求，界面也仍然显示这个按钮。此处没有断言规则的保存期限；具体影响范围须由适配层按当前协议明确给出。
- 在 320px、英文、五主题及两种布局下，“Allow for this session”都超出按钮内部宽度。current 布局按钮内部约 81px，内容滚动宽度 137px；console 布局内部约 86px，内容仍为 137px。页面整体没有溢出，但按钮文字被遮挡。

实现定位：[审批渲染](../../packages/codex-web/public/app.js#L2992)、[通用摘要](../../packages/codex-web/public/app.js#L4068)、[卡片样式](../../packages/codex-web/public/styles.css#L2571)、[审批按钮](../../packages/codex-web/public/styles.css#L4409)、[窄屏 nowrap](../../packages/codex-web/public/styles.css#L5931)、[实际决定映射](../../packages/codex-native-api/src/codex_app_client.ts#L2738)。

建议设计为对话内的审批组件，保留审批上下文和输入区的关系。采用“请求目的 → 实际操作 → 授权范围 → 操作”的顺序。命令使用现有等宽字体和独立代码区域；工作目录适度弱化但可查看完整路径；协议字段进入可展开详情，决定授权范围的信息保持可见。按钮按实际可用决定生成，不固定三个等宽大按钮。窄屏允许操作区换行，不靠缩小文字容纳长标签。

```text
需要执行命令                              等待处理
为检查页面，需要启动本地浏览器测试站点。

┌ 命令 ───────────────────────────────┐
│ node …/fixture-server.mjs --port=41759 │
└────────────────────────────────────┘
工作目录  …/codex-mobile-web-app       查看详情

本次操作的授权范围说明
[允许本次]  [拒绝或取消：按实际语义命名]
其他可用授权方式及其范围
```

这是信息层级示意，不是最终视觉稿。实际实现必须允许查看完整命令，不能用示意图中的省略号掩盖执行内容。执行命令、文件改动、网络访问等审批可以共享外壳，但正文应按实际种类组织。

待处理、正在发送、结果未确认、已处理、已失效分别设计。已处理项可收敛为简短结果行；结果未确认仍禁止盲目重复提交。扩展规则与仅本次允许必须有不同的动作描述。

### FD-02：管理控制台按整套页面重构

证据：[桌面会话审计](2026-09-25-frontend-design-review-evidence/desktop-admin-sessions.png)、[980px 分栏](2026-09-25-frontend-design-review-evidence/desktop-admin-boundary-980.png)、[桌面项目编辑](2026-09-25-frontend-design-review-evidence/desktop-admin-project-editor.png)、[手机项目列表](2026-09-25-frontend-design-review-evidence/mobile-admin-projects.png)、[手机用户编辑](2026-09-25-frontend-design-review-evidence/mobile-admin-user-editor.png)、[系统页](2026-09-25-frontend-design-review-evidence/desktop-admin-system.png)。

这里主要是整体设计问题，并非现有页面普遍不可用。已确认编辑表单能获得初始焦点，手机编辑时会隐藏集合列表，系统表格也有独立横向滚动容器；这些已有行为值得保留。

需要统一的具体内容：

- **页面结构与空间分配。** 会话审计的筛选表单、会话卡片和详情区各占一层容器。未选择会话时，1440px 下仍保留约 840px 的空详情区。建议按“筛选和查找 → 选择记录 → 查看详情”组织；宽屏保留分栏，边界宽度按可读性切换，不把稀疏 fixture 数据造成的留白误判为布局溢出。
- **标题与正文层级。** 许多页面标题、集合标题、编辑标题都为 14px，表单标签却为 16px。项目使用表格，用户和角色使用另一套卡片；手机项目表格转换后又重复“显示名称、CWD、状态、操作”等标签。应统一标题规格、行高、字段优先级和主要操作位置。
- **身份与权限可读性。** 用户行把用户 ID、邮箱、角色 ID 拼成一串次要文字。建议突出用户名、状态与角色名称，将内部 ID 放到详情中；角色页清楚说明当前已有权限，不借视觉改造擅自扩大授权能力。
- **确认交互。** 删除用户和关闭多用户模式使用 `window.confirm`，而会话归档、Webhook 换钥等使用站内对话框。已在 fixture 打开并取消删除确认，记录到原生 `confirm`，管理写请求为 0。建议统一为现有主题下的确认组件，说明对象与影响，保留取消和错误反馈。
- **系统页层级。** 构建 ID、运行秒数、请求延迟、存储限额、设备与多用户开关平铺。可组织为服务概况、请求指标、存储与设备；运行时间用易读单位，并保留精确值。当前快照数据不支持趋势图或健康结论，不能凭空绘制趋势或把没有采样当成零延迟。

实现定位：[管理台渲染](../../packages/codex-web/public/admin-ui.js)、[管理样式](../../packages/codex-web/public/styles.css#L1381)、[按需编辑与手机适配](../../packages/codex-web/public/styles.css#L5935)、[关闭团队模式确认](../../packages/codex-web/public/app.js#L4549)、[删除用户确认](../../packages/codex-web/public/app.js#L4725)。

建议保留五个业务分区：会话审计、项目、角色、用户、系统。桌面使用稳定侧栏、内容区和按需详情/编辑区；手机使用清楚的分区入口与独立详情/编辑页面。先统一页面骨架与控件，再逐页替换。搜索、大集合分页可按真实规模单列后续功能，不能把仅搜索已加载部分数据呈现为全量搜索。

### FD-03：启动失败缺少恢复界面

证据：[关键脚本失败 15 秒后](2026-09-25-frontend-design-review-evidence/boot-failure-after-15s.png)、[存储读取失败](2026-09-25-frontend-design-review-evidence/boot-failure-storage.png)、[错误记录](2026-09-25-frontend-design-review-evidence/results.json)。

无已有 Service Worker 缓存的首次访问中，阻止 `app.js` 下载后只显示 Codex 和加载条；等待 15 秒仍无错误说明或重试入口。阻止 `admin-data.js` 下载，会因顶层解构未定义对象报错；模拟 `Storage.getItem` 抛 `SecurityError` 也会在启动阶段中断。

这是首次加载/启动失败的边界，不代表已有 SSE 重连或 PWA 完整缓存保护失效。源码定位：[启动壳](../../packages/codex-web/public/index.html)、[模块依赖](../../packages/codex-web/public/app.js#L7)、[未防护的启动存储读取](../../packages/codex-web/public/app.js#L130)。

建议让启动壳具备不依赖主应用成功执行的失败提示与重新加载入口；对依赖加载和初始化异常显示不同原因。把偏好、令牌等存储读取纳入安全访问，存储不可用时说明登录/持久化限制，不能伪造已登录身份或声称缓存已恢复。继续保留 Service Worker 的完整版本切换与有界缓存。

### FD-04：工作详情的键盘导航缺陷

在全部工作项折叠时，弹窗中有审批、运行、编辑三个可见 `summary`。连续按 12 次 Tab，焦点在第一个审批 `summary` 和关闭按钮之间交替，无法自然到达后两个工作项。

原因是 [focusableElements](../../packages/codex-web/public/app.js#L1115)没有包含 `summary`，却包含折叠内容中的不可见 `pre[tabindex]`。[Tab 处理](../../packages/codex-web/public/app.js#L1145)把当前 `summary` 视为不在候选集合中，强制回到第一个候选。详见 [实际焦点序列](2026-09-25-frontend-design-review-evidence/followup-results-work-focus-check.json)。

建议修正可聚焦元素判定，处理 `summary`、不可见祖先、折叠内容和 inert；回归 Tab、Shift+Tab、Escape、焦点返回及展开后的代码滚动。现有焦点管理与背景 inert 机制应继续使用。

### FD-05：附件失败卡片的操作区拥挤

证据：[上传中](2026-09-25-frontend-design-review-evidence/mobile-attachment-progress.png)、[失败后](2026-09-25-frontend-design-review-evidence/mobile-attachment-failed.png)。

390px 手机宽度下，长文件名上传失败后，“重试”变为两行，按钮伸出卡片预留列，移除按钮落到下一行。当前 [附件 grid](../../packages/codex-web/public/styles.css#L3360)定义三个列位，但 [失败态增加重试按钮](../../packages/codex-web/public/app.js#L2346)后有四个控件。移除按钮为 28×28px，虽不应直接判为不满足 WCAG 2.2 的 24px 最低目标规则，但对手机操作仍偏小。

建议把文件名/大小、进度或失败状态、操作区分开布局；失败后在稳定位置显示完整“重试”，移除操作使用更舒适的触控区域。保留逐文件进度、取消、重试、并发限制与草稿归属。这是局部样式修复，不需要更换上传实现。

### FD-06：全局设置窗口整体调整

证据：[桌面设置上部](2026-09-25-frontend-design-review-evidence/desktop-app-settings-top.png)、[桌面设置下部](2026-09-25-frontend-design-review-evidence/desktop-app-settings-bottom.png)、[手机设置](2026-09-25-frontend-design-review-evidence/mobile-app-settings-top.png)、[手机下部](2026-09-25-frontend-design-review-evidence/mobile-app-settings-bottom.png)、[集成设置](2026-09-25-frontend-design-review-evidence/mobile-webhook-enabled.png)。

桌面窗口确实存在独立于内容分组的整体问题。它以 `.desktop-settings-panel` 绝对定位在聊天区域左侧和底部，最大宽度 460px；1440×900 的截图中面板从约 x=454 延伸到 x=914，几乎占满高度，压住聊天内容却不是居中的对话框或贴边抽屉。实现声明 `aria-modal=true` 且背景已 inert，但没有与其他模态一致的视觉遮罩，外观像可并行使用的浮层，实际却不能操作背景。

内部也混用不同规格：设置标题、区块标题、字段说明普遍偏小，语言和权限选项使用大片强调色，设备区又出现明显偏扁的全宽按钮；输入框、选项卡、开关与操作按钮的边框、留白和高度不统一。这些需要一起调整。

当前 390×844 下，加载设备前设置内容高度约 1474px，可视区 777px。长度本身不是缺陷；问题是网站标题、外观、新会话默认值、Webhook、运行时、账户按同一层级连续出现，缺少快速定位。桌面也在单个窄侧面板中承载这些内容。

建议桌面采用明确的设置对话框：在完整工作区中居中、限制合适宽高、配套轻遮罩、稳定标题栏，内容分为分组导航和设置区域；手机继续使用完整设置页，分组可逐级进入。这样设置的作用范围和打开/关闭关系更清楚。关闭后返回原会话与原阅读位置，背景任务继续按原机制运行。

内容分成“外观与语言、会话默认值、外部集成、账户与设备、高级”。统一输入、选择、开关和按钮规格，明确“仅此设备”和“服务端全局”的设置范围，不能只因窗口统一就混淆其保存对象。Webhook 可使用“外部集成 / Webhook”作为入口，保持技术用户能识别其用途；密钥增加显隐控件，保留复制和原有换钥确认。不要把 Webhook 错称为已实现的通知系统。

实现定位：[桌面设置窗口](../../packages/codex-web/public/app.js#L1767)、[窗口定位](../../packages/codex-web/public/styles.css#L5146)、[设置分区](../../packages/codex-web/public/app.js#L1781)、[Webhook](../../packages/codex-web/public/webhook-settings.js)。设置改动仍须保留编辑中状态、异步保存反馈、嵌套换钥确认的焦点返回和阅读位置。

### FD-07：统一语言与格式

英文模式的新会话页仍显示中文“开启新会话”，因为 [标题](../../packages/codex-web/public/app.js#L1917)写死且有 `data-i18n-skip`。中文模式的审批/工作详情仍显示 `Reason`，用户编辑显示 `Email`；这些 UI 标签与用户命令或文件原文应区别处理。

日期使用 [浏览器默认 locale](../../packages/codex-web/public/app.js#L13587)，没有跟随站内语言。因此在英文浏览器切中文界面仍出现 `Jul … PM`，不是所有中文设备都必然出现英文日期。

建议补齐翻译表、语义化字段名与语言选择对应的日期格式，保留模型标识、命令、路径和用户内容原文。验收包括中英文切换、长标签、消息字号偏好与至少 320px 宽度。

### FD-08：空白和错误页给出下一步

使用服务端当前 `session_not_found` / `Selected session was not found.` 的真实 404 响应形状模拟分享链接不可用，中文界面只居中显示英文原始错误，没有恢复说明：[截图](2026-09-25-frontend-design-review-evidence/mobile-share-unavailable-404.png)、[响应检查](2026-09-25-frontend-design-review-evidence/followup-results-share-real-404-shape.json)。普通分享阅读页保持轻量只读，本身无需添加管理导航。

建议无效、已撤销、过期或不可见的分享统一显示“分享链接不可用”，提示向分享者索取新链接，继续保持服务端对外不区分敏感原因的边界。临时网络错误可以提供重试；不能对无权访问情况诱导反复重试。登录、文件打开、管理列表加载错误也采用一致的标题、原因和操作布局，保留原有局部重试能力。

实现定位：[分享空状态](../../packages/codex-web/public/app.js#L1501)、[分享权限校验](../../packages/codex-web/src/server.ts#L2360)、[404 形状](../../packages/codex-web/src/server.ts#L7419)。

## 视觉方向与实施次序

延续现有主题变量。清新白参考色为背景 `#f4f5f7`、侧栏 `#eaecef`、表面 `#ffffff`、正文 `#1f2937`、次要文字 `#6b7280`、强调色 `#10b981`；最终使用对应主题 token 与现有对比度修正，不把参考值硬编码到五种主题。保留当前中文/系统字体与代码等宽字体。

审批与管理页面建议正文以 14–16px 为主，12px 只承载辅助元数据；标题、说明、命令和动作拥有不同层级。延续现有圆角、柔和表面与克制的强调色，让边框区分内容区域，避免给每一行再套一张卡片。主要内容左对齐，文字和按钮不会因语言变长而被裁切。动效仅用于解释打开、关闭和状态变化，继续支持减少动态效果的偏好。

| 批次 | 实施内容 | 可验收成果 |
| --- | --- | --- |
| 1 | 审批请求组件重做，明确动作与授权范围 | 五主题、两布局、中英文、窄屏、长命令及完整审批状态对照；实际决定与标签一致 |
| 2 | 全局设置窗口重做，建立统一的对话框、控件和分组结构 | 桌面/手机设置完整预览；各设置保存范围、草稿、焦点和阅读位置回归 |
| 3 | 管理台统一骨架，再迁移会话审计、项目、角色、用户、系统 | 桌面/手机完整页面与编辑流程；复用统一确认组件；原有权限和保存行为回归 |
| 4 | 启动恢复、键盘导航、附件失败操作区，以及翻译、空白/错误页 | 故障注入与针对性行为测试通过；页面反馈与恢复入口一致 |

批次 4 的独立缺陷可在窗口与管理台重构期间先修；上述顺序表达用户关注的产品优先级，不要求把小修复拖到大重构全部完成。
